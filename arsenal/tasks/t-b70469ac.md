From the test-diet pass of the repo review of 2026-11-11. Nothing was changed; tick or delete as triaged.

**Numbers:** test_files=87, tests=1523, test_lines=25354, source_lines=17909, suite_seconds=102, ci_jobs_per_push=1, ran_suite=True, note=102s wall / 140s summed test time on 4 cores, vitest run without coverage, 1523/1523 pass. CI runs it with v8 coverage (not timed). Other CI steps measured locally: lint 18s, typecheck 8s, build 4s. install 5s warm.

**Estimated saving:** ~40% of every-push test time (140 -> ~80 test-seconds; ~102s -> ~60s wall on 4 cores), derived from per-test durations in the vitest JSON report: chatgpt read-only describes 14s -> ~2s, popup per-test reload 60s -> ~20s (router file as the baseline), gemini ~3s, waitfor test 1.5s. Under 1% of test lines actually deleted (~150 lines). Docs-only path filter and cancel-in-progress save whole runs on top.

- The suite is large (1.4:1 test:source lines) but mostly proportionate in COST: 72 of 87 files finish in under 2s each and together take ~25s of the 140 test-seconds. This is not a 'too many tests' problem, it is a 'two harness patterns' problem.
- 73% of test time is in two places: the popup files (190 tests, 60s) and the parser files (209 tests, 39s; chatgpt.test.ts alone 27s). Both are slow for the same reason: an expensive fixture is rebuilt per test (vi.resetModules + re-import of the whole popup module graph; JSDOM re-parse of a 260KB capture in beforeEach).
- Proof the popup cost is harness, not behaviour: popup-router.test.ts imports the module once and its 57 tests have a 19ms median; the sibling files that resetModules per test have 380-620ms medians for the same module.
- Single biggest win: share the loaded popup / parsed DOM across read-only tests (beforeAll or one test with several expects). Roughly 55-60 of 140 test-seconds, no test deleted.
- Genuinely cuttable tests exist (toBeDefined selector checks, grep-the-source tests, a 1.5s sleep test) but they are ~15 tests and ~2s; cutting them is hygiene, not speed.
- CI is one job on one OS with pnpm cache: fine. Tests are ~75% of its compute. Gaps: no concurrency cancel, no docs path filter, the build runs twice (pnpm build, then package:all runs pnpm build again), coverage on every PR.

### Cuts and moves
- [ ] **[slow-tier] Popup tests re-import the whole popup module graph for every test** (133 tests) — 8 popup files call vi.resetModules() + await import(popup) + waitFor in a per-test loadPopup(); 133 tests cost 57s (median 380-620ms each in states/settings/filename/options/pair-chooser). popup-router.test.ts loads once and runs 57 tests in 3.7s. Not a tier problem to defer, a harness problem to fix; category is the closest fit. `tests/unit/extension/popup/popup-{states,settings,filename,ready,options,pair-chooser,format-menu}.test.ts, popup.test.ts (loadPopup helpers, e.g. popup-settings.test.ts:89-97)`
  - Protection lost: none — same assertions; tests that only read the freshly booted popup share one boot per describe, tests that need a clean module keep the reset
  - Action: Group tests by starting state and boot once per describe (beforeAll loadPopup, reset DOM/storage stubs in beforeEach) as popup-router already does; alternatively vi.mock the heavy static imports popup.ts pulls in (core/parsers registry) so a re-import is cheap. Extract the 8 copies of loadPopup/EN_MESSAGES/MANIFEST into tests/utils while there.
- [ ] **[duplicate] chatgpt.test.ts re-parses a 260KB capture with JSDOM before every test** (31 tests) — Two beforeEach blocks (lines 145, 229) build a JSDOM from real-capture.html (260KB) for each of ~35 tests, and the 9 parse() tests each call parser.parse() again to assert one field (success, platform, pair count, index, selected, ids...). parse() describe = 8.7s, 'selector matching on real DOM' = 2.6s, 'DOM fixture validation' 0.9s, edge cases 2.2s (rebuild the big DOM, then use a tiny inline one). `tests/unit/core/parsers/chatgpt.test.ts:140-360`
  - Protection lost: none — one parse of the same fixture, same expects; parse() result is not mutated by these tests
  - Action: Move the fixture DOM + parser.parse() into beforeAll for the read-only describes (or collapse the 9 parse() field checks into 2-3 tests); move the 'edge cases' describe out from under the real-capture beforeEach since each builds its own DOM.
- [ ] **[slow-tier] ChatGPT drift-resilience tests parse the 260KB fixture two to three times each** (4 tests) — 4 tests take 9.3s (4.4s, 1.9s, 1.8s, 1.2s): each gets the beforeEach DOM, then freshParser() re-reads and re-parses real-capture.html for a baseline and runs parse() twice. Valuable (this is the failure mode that silently zeroed the parser) but the baseline is a constant. `tests/unit/core/parsers/chatgpt.test.ts:512-612`
  - Protection lost: none — baseline pair count computed once in beforeAll
  - Action: Compute the baseline pair count once (beforeAll); keep one fresh mutable DOM per test. Optionally run drift tests against a trimmed 3-turn capture.
- [ ] **[duplicate] Same per-test JSDOM rebuild in gemini, block-flattening and pagination** (69 tests) — gemini.test.ts (33 tests, 6.7s) builds new JSDOM(html) from 106-266KB fixtures inside most tests; integration/block-flattening.test.ts (32 tests, 5.3s) and gemini-table-fidelity (4 tests, 2.2s) follow the same shape. pagination.test.ts (8 tests, 5.2s) renders real jsPDF documents and is legitimately heavy. `tests/unit/core/parsers/gemini.test.ts:27-300, tests/integration/block-flattening.test.ts, tests/unit/core/services/gemini-table-fidelity.test.ts`
  - Protection lost: none for read-only tests sharing a parsed document; leave pagination.test.ts alone
  - Action: Parse each fixture once per describe (beforeAll) and reuse the Document for tests that do not mutate it.
- [ ] **[ci-config] CI builds twice and never cancels superseded runs or skips docs-only pushes** (0 tests) — ci.yml runs `pnpm build` then `pnpm package:all`, which itself runs `pnpm build` again (and build:chrome and build:firefox each re-run build:content). There is no `concurrency: cancel-in-progress`, and no paths-ignore, so a docs/, arsenal/ or claude-arsenal/ only push pays the full lint+typecheck+coverage+build job. Build is only ~4s locally, so the real saving is the skipped/cancelled runs. `.github/workflows/ci.yml:6-36; package.json scripts build/package:all/build:chrome/build:firefox`
  - Protection lost: none — docs and vendored-skill changes cannot affect the extension; keep the job required via a no-op path for skipped runs if branch protection needs it
  - Action: Add `concurrency: {group: ci-${{ github.ref }}, cancel-in-progress: true}`; add paths-ignore for '**.md', 'docs/**', 'arsenal/**', 'claude-arsenal/**', '.claude/**'; replace the final `pnpm package:all` with `node build/package-all.cjs` after the existing build + manifest check.
- [ ] **[ci-config] Coverage instrumentation runs on every PR push** (0 tests) — CI runs `pnpm test:coverage` (v8 coverage + thresholds) as the only test step. The thresholds are a slow-moving ratchet (set ~1.5 points under measured), not a per-push signal; v8 coverage adds overhead to a suite that already starves its own timeouts (testTimeout raised to 15s, waitFor default raised to 15s for CPU contention). `.github/workflows/ci.yml:27; vitest.config.ts:26-58`
  - Protection lost: small: a coverage drop is caught on merge to main instead of on the PR
  - Action: Measure once (`time pnpm test:coverage` vs `time pnpm test:run`); if the delta is >20%, run `test:run` on pull_request and `test:coverage` on push to main.
- [ ] **[meta] waitfor-timeout test sleeps 1.5s to test the test setup** (2 tests) — A test whose subject is tests/setup/vitest.setup.ts: it waits 1500ms of real time to prove the patched vi.waitFor default exceeds 1000ms. 1.6s for 2 tests, about 1% of suite time, protecting test infrastructure rather than the product. `tests/unit/waitfor-timeout.test.ts`
  - Protection lost: small: a vitest upgrade that drops the patch would show up as popup waitFor flakes instead of one clear failure; a spy-based assertion (patched fn passes timeout 15000) keeps the guard at 0s
  - Action: Replace the real sleep with fake timers or assert the option forwarded by the wrapper; or delete once finding 1 removes most per-test waitFor boots.
- [ ] **[trivial] toBeDefined checks on the selector constant** (5 tests) — 5 tests assert that CHATGPT_SELECTORS properties are defined (17 expects). The 28-case 'selector liveness' block right below already iterates every selector and requires it to match a fixture node, and TypeScript types the object. `tests/unit/core/parsers/chatgpt.test.ts:40-71 (same pattern likely in claude.test.ts / gemini.test.ts selector blocks)`
  - Protection lost: none — covered by 'selector liveness against the committed fixtures' (it.each over every selector) and tsc
  - Action: Delete the CHATGPT_SELECTORS describe.
- [ ] **[meta] Grep-the-source and compile-time tests that belong in lint/tsc** (8 tests) — content-script-log-prefix (2 tests regex the source for a literal and an import statement), no-debug-logging (4 tests grep 4 files for console.log; eslint no-console scoped to those files does it), constants.test.ts (2 tests whose own header says 'compile-time checks... pnpm typecheck is what actually enforces them'). ~80 lines, ~0s. `tests/unit/extension/content/content-script-log-prefix.test.ts, tests/unit/core/no-debug-logging.test.ts, tests/unit/shared/constants.test.ts`
  - Protection lost: none if moved: an eslint no-console override for the hot-path files and no-restricted-syntax for the literal; constants covered by tsc already
  - Action: Move the two source greps into eslint.config.js rules, delete constants.test.ts. Hygiene only; no CI time.
