## What changed

ChatGPT renders fenced code through an embedded **CodeMirror 6** viewer:

```
pre.overflow-visible!            <- markdown wrapper, carries data-start/data-end
  div#code-block-viewer.cm-editor
    div.cm-scroller
      pre.cm-content             <- a SECOND <pre>
        code                     <- NO class
          span                   <- body text, real newlines inside
```

Measured live: 8 `<pre>` on a page with 4 code blocks (4 outer + 4 inner).

## Three distinct problems

1. **Nested `<pre>` → duplicate blocks.** A `pre code` walk matches both the outer
   wrapper and the inner `cm-content`. Extract the outer one and skip anything
   inside a `.cm-editor`, or extract the inner and skip the wrapper — pick one.
2. **Language is gone.** `div.h-9` (the old label) and `code[class*="language-"]`
   both match 0; `code` has no class at all. Either find a real source for the
   language or **drop it honestly** — do not guess from the code body.
3. **Virtualization risk.** CodeMirror renders only visible lines for large
   documents, so a long block may be partially present in the DOM. Not reproduced on
   the short blocks in the fixture (one `<span>` held the whole body with real
   newlines), but a long-code case must be checked. If truncation is detectable,
   report it rather than exporting a silently-truncated block.

Investigate (3) with a real long code block before deciding it is a non-issue. Say
what you found either way.
