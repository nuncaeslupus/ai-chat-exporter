Split out of `lo-a23a` (D-35, merged as #205). That task had two halves:

1. **The safety net — DONE in #205.** Block elements no longer flatten into one run.
   A Gemini table now renders as separated cells (`" | "` between cells, newline
   between rows) instead of `0 EUR19%De 6.000 EUR`. **The data corruption is fixed.**
2. **Recognising Gemini's table markup — NOT DONE**, and correctly so.

## Why half remains

The #205 worker verified that **the Gemini fixtures contain no table at all**:

```bash
grep -c '<table' tests/fixtures/dom-snapshots/gemini/*.html    # 0 in both
```

and none of the strings from the owner's real export ("Tabla", "Jurisdicción",
"Base Liquidable", "European Systematic Equity") appear anywhere in
`tests/fixtures/dom-snapshots/gemini/`. The fixtures **predate** that conversation.

So there is nothing to derive a selector from. Guessing at Gemini's markup would be
exactly the kind of speculative selector that the drift work (SD-1..SD-9) exists to
prevent.

## What this task needs

**A fresh DOM capture of a Gemini answer containing a table.** Use the
`parser-generator` skill — it owns capture and selector derivation. Then:

- Identify the element that actually carries the rows (candidates: `role="table"`,
  a CSS-grid container, or repeated sibling divs — **determine it, do not assume**).
- Add the selector to `GEMINI_SELECTORS.custom` and emit `type: 'table'` blocks
  from the Gemini path so `HtmlContentParser`'s existing table handling and every
  exporter's existing table renderer take over.
- Add the capture as a fixture so this is regression-tested rather than trusted.

## Also worth capturing while you are in there

The same real export showed two more Gemini-specific shapes that #205's separator
fix improved but did not structure properly:

- The research-plan widget: `Analyze ResultsCreate ReportReady in a few mins` and
  `...Research Websites(1) Find official fee schedules...` — a numbered plan rendered
  as one blob rather than a list.
- `European Systematic Equity Cost AnalysisJul 24, 9:50 AM` — a title and timestamp
  that belong in separate fields.

If the capture reveals clean structure for these, model them; if not, say so.

## Do not regress #205

The separator behaviour in `src/core/utils/dom-text.ts` is the safety net for every
platform. If a real `type: 'table'` block now supersedes it for Gemini, the fallback
must still apply to any structure you do NOT recognise. Run
`tests/integration/block-flattening.test.ts` and the full suite.

## Acceptance gate

A captured Gemini table renders as a real table in all six formats, and unrecognised
structures still fall back to separated text rather than concatenation.

```bash
pnpm test:run tests/integration/ tests/unit/core/parsers/ tests/unit/core/services/ && pnpm lint && pnpm format:check && pnpm typecheck
```

Requires a live Gemini page for the capture, so the capture step is owner-assisted;
state clearly in the PR what was captured and when.
