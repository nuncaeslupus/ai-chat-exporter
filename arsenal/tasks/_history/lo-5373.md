**Owner decision, 2026-07-30.** This task exists because the first attempt at
D-25 (`lo-6fbb`) fixed the symptom in a way that erodes a real signal. The owner
chose this route instead. D-25 now depends on this task and applies the filter
once 4.x is in.

## Why

`pnpm test:coverage` exits 1 on a green suite because of an unhandled
`[vitest-worker]: Timeout calling "onTaskUpdate"` RPC error. In vitest **3.2.4**
the only knob that clears it is `dangerouslyIgnoreUnhandledErrors`, a boolean
that suppresses **every** unhandled error in **every** invocation — a future
genuine unhandled promise rejection would stop failing the suite too. Vitest
**4.x** adds the `onUnhandledError` callback, which can suppress that one RPC
message by pattern and keep failing on everything else. That is the fix; this
upgrade is the vehicle.

## Established by the prior investigation (do not re-derive)

- The birpc timeout in 3.2.4 is hardcoded (60s `DEFAULT_TIMEOUT` in
  `vitest/dist/chunks/index.B521nVV-.js`) and is reachable through **no** public
  config surface — not `testTimeout`, `hookTimeout` or `teardownTimeout`
  (`WorkerRpcOptions` only picks `on|post|serialize|deserialize`).
- `poolOptions.threads.maxThreads: 4` **measurably does not clear it** — same
  ~81s wall clock, same single unhandled error, still exit 1. Do not retry it.
- Upstream, known and unresolved: vitest-dev/vitest #6479, #8164, #4497.
- Latest vitest at time of writing: **4.1.10**.

## Scope

The upgrade ONLY. Do **not** add any suppression in this PR — that is `lo-6fbb`.

- Bump `vitest` (and `@vitest/coverage-v8` — keep the versions in lockstep, a
  mismatched coverage provider is the usual breakage) in `package.json`.
- Work through the 3 -> 4 breaking changes across **69 test files / 1170 tests**.
  Expect churn in mock APIs, `environmentMatchGlobs` (removed in favour of
  per-file annotations), and coverage-provider config keys.
- The suite must end at **1170 passing** — a drop in test count is a silent
  regression, not a pass. State the before/after counts in the PR.
- Coverage thresholds must still be enforced, not merely configured: the repo has
  a prior defect (`lo-2b62`) where thresholds were ignored. Confirm the floor
  still fails when violated.
