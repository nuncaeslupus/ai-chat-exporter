Found while wiring the ChatGPT logo to its brand token (`lo-cfc6` / #200). Not
speculative — both values are in the repo today:

| Source | Value |
| --- | --- |
| `src/assets/icons/claude-logo.svg` (`fill`) | **`#D97757`** |
| `COLOR.brand.claude` in `style-tokens.ts` | **`#cc7b58`** |

For comparison, the other two now agree with their marks:
`COLOR.brand.chatgpt` = `#10a37f` (matches the logo as of #200), and
`COLOR.brand.gemini` = `#4285f4`, which is Google Blue 500.

## Why it matters

`COLOR.brand.*` drives html's brand rule and pdf's role label — the accent beside
the role label. So a Claude export can show the **logo in one shade and the brand
rule in another**, in the same document, a few pixels apart. That is a visible
inconsistency, not a theoretical one.

It also blocked a guard: #200 added an assertion coupling `chatgpt-logo.svg`'s
fill to `COLOR.brand.chatgpt`, and the equivalent assertion for Claude could not
be added because the two values differ. Reconciling this unlocks that guard.

## The decision this needs — and it is not a guess to make

**Establish which value is the vendor's actual brand colour, from Anthropic's own
press kit / brand guidance.** Do not pick whichever looks nicer, and do not
average them.

The standing repo rule is that platform marks come from the vendor's press kit and
are never approximated. The same should hold for the accent colour drawn beside
them. Note the `COLOR.brand` comment says "pdf's original values are canonical",
which suggests `#cc7b58` may simply be an early value that predates the logo asset
and was never reconciled — but **verify that, do not assume it**.

Then:
- If the logo's `#D97757` is the vendor value -> update `COLOR.brand.claude`, and
  re-derive `COLOR.brandTextOnLight.claude` (currently `#A65532`) from it, since
  that variant exists to keep the label legible on a light surface.
- If `#cc7b58` is somehow the vendor value -> the **logo asset** is the wrong one,
  and it must be replaced with the press-kit file rather than hand-edited.
- If neither is authoritative -> report that and stop. Do not invent a third
  value; bring it back for an owner decision.

## Knock-on checks

- `COLOR.brandTextOnLight.claude` (`#A65532`) is a darkened variant of the brand
  colour for text on light surfaces. If the base changes, re-derive it and re-run
  the contrast gate — it exists to meet AA and must still meet it.
- `tests/unit/accessibility/contrast.test.ts` covers brand pairs; any change must
  keep every Claude pair passing.
- Once the two agree, **add the coupling assertion** for `claude-logo.svg` mirroring
  the ChatGPT one from #200 (read the file, compare its fill to
  `COLOR.brand.claude`, case-insensitive, either quote style), and prove it fails
  when the fill is broken.

## Do not touch Gemini

`gemini-logo.svg` is a multi-colour mask + gradient mark with no single fill.
There is nothing to reconcile and nothing to assert.

## Acceptance gate

The Claude logo and `COLOR.brand.claude` are the same, vendor-sourced value; the
`brandTextOnLight` variant is re-derived if the base moved; every contrast pair
still passes; and a coupling assertion guards the pairing.

```bash
pnpm test:run tests/unit/accessibility/contrast.test.ts tests/unit/core/exporters/ && pnpm lint && pnpm format:check && pnpm typecheck
```
