Dependabot PR **#103** (`vite` 6.4.1 → 8.1.5) is the one bump of the five that
does **not** merge cleanly. Left open deliberately.

## What actually breaks

Vite 8 replaces Rollup with **Rolldown**, whose plugin type does not carry
`renderDynamicImport`:

```
build/vite.content.ts(55,3): error TS2345: Argument of type 'UserConfig & …'
  is not assignable to parameter of type 'never'.
build/vite.content.ts(75,13): error TS2769: No overload matches this call.
  'renderDynamicImport' does not exist in type 'Plugin<any> | ParallelPlugin |
  … | RolldownPluginOption<any>[] | …'
```

The hook at `build/vite.content.ts:75` rewrites every dynamic import to an
absolute `chrome.runtime.getURL("assets/…")` URL:

```ts
renderDynamicImport() {
  return {
    left: 'import(chrome.runtime.getURL("assets/"+',
    right: '.split("/").pop()))',
  };
}
```

**This is load-bearing.** A dynamic import's relative specifier resolves against
the *page* origin once the loader has run, not the extension's, so without the
rewrite every lazily-loaded chunk 404s on a real page. It is what makes the
lazy-loaded content-script bundle work at all, and `pnpm build` has a dedicated
`N lazy chunk URL(s) resolve` check guarding it.

## The trap

Measured on 2026-07-30: under Vite 8 `pnpm build` **succeeds** and that lazy
chunk check still passes — only `tsc` fails. Do not read the green build as
"it works": vite does not typecheck its own config, and the check verifies the
emitted URLs, not that the hook ran. Verify on a **real extension page** that a
lazily-loaded chunk still resolves, not just that the build exits 0.

## The work

Find Rolldown's equivalent. Options to evaluate, in order of preference:

1. A Rolldown-native hook or option that rewrites dynamic-import specifiers.
2. `experimental.renderBuiltUrl` / `output.chunkFileNames` + a base URL, if it
   can express `chrome.runtime.getURL`.
3. A `renderChunk`/`transform` post-pass that rewrites the emitted
   `import("./chunk-x.js")` calls textually — the crude fallback; take it only if
   1 and 2 genuinely cannot express this, and say so.

## Acceptance gate

Typecheck passes under Vite 8, both builds succeed, the lazy-chunk check passes,
**and** a lazily-loaded chunk is confirmed to resolve on a real chat page.

```bash
pnpm typecheck && pnpm lint && pnpm format:check && pnpm test:run && pnpm build
```

The bash block cannot prove the last clause — the live-page check is manual and
must be stated in the PR.
