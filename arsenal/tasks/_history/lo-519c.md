## Acceptance gate

**Gate**: `pnpm dev:chrome` produces an unminified bundle with a `.map` alongside it; `pnpm dev` either works or is gone.


Prose-only gate — verified by worker judgment, no script to run.

## Two bugs

1. `package.json:7` — `"dev": "vite build --watch --mode development"` has no `--config`, so vite looks for `vite.config.ts` at the repo root, which does not exist (the real one is `build/vite.config.ts`). Verified: fails with `Could not resolve entry module "index.html"`. Every sibling script passes `--config`. Delete it or alias it to `dev:chrome`.
2. `build/vite.config.ts:20-21` keys sourcemaps and minification off `process.env.NODE_ENV`, which `--mode development` does not set — vite's `build` command defaults `NODE_ENV` to `production` regardless of `--mode`. Verified empirically: the "development" watch build emits a minified single-line bundle with no `.map`. Use the config-function `mode` argument instead.

## Context

Combined effect: the documented dev loop ships production-shaped code, so anyone debugging in the browser has been reading mangled output. Cheap fix, disproportionate daily payoff.
