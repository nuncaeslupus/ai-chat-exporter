## Acceptance gate

**Gate**: a conversation containing a web search and a numbered list exports with the list intact in all six formats.


Prose-only gate — verified by worker judgment, no script to run.

## The defect

`src/core/services/conversation-structure-service.ts:46-58`:

```
const hasSpecialContent = message.metadata?.webSearches || message.metadata?.artifacts;
const blocks = hasSpecialContent
  ? [{ type: 'paragraph', content: [{ type: 'text', text: message.content }] }]
  : message.htmlContent ? HtmlContentParser.parse(message.htmlContent) : ...
```

When a message has either metadata field, `htmlContent` is **discarded entirely** and the flattened `message.content` — built as `clone.textContent?.trim()` in `base-parser.ts` — becomes one paragraph.

Verified in jsdom: `<ol><li>First point</li><li>Second point</li></ol>`.textContent === `"First pointSecond point"`. No separator. Lists, tables, headings and code blocks all collapse into one run-on paragraph.

This is not an edge case: any answer that triggers a web search or produces an artifact hits it, on all three platforms, in every export format (all six route through this service).

## Fix

Parse `htmlContent` as normal and append the special-content markers as additional blocks, rather than replacing the parsed blocks with flattened text.
