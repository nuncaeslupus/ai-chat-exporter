`lo-c03f` claims "Content script bundle is 2.24MB injected on every page load:
lazy-load exporters". That is no longer true and the task should be closed.

**What the spec requires:** the eager content-script bundle stays small enough
that the PDF's embedded fonts cost nothing at page load.

**What the code does:** already satisfies it. Commit `7dc276a` landed the split.
`src/core/exporters/index.ts` is a registry of `import()` factories and the
barrel deliberately does not re-export the concrete classes, so a static edge
cannot pull them back into the eager graph. Measured with `pnpm build:content`:

```
ok dist/chrome: 57.422 B eager (limit 307.200 B, 3 file(s))
  ok dist/chrome: 13 lazy chunk URL(s) resolve
```

57 KB eager against a 300 KB build-time gate, with jsPDF (388 KB), docx
(360 KB) and html2canvas (202 KB) all in lazy chunks.

**Fix location:** none in code. Close `lo-c03f`. The only requirement carried
forward is recorded in R-2 (`lo-2fa9`): import the font module from
`pdf-exporter.ts`, never from the barrel.
