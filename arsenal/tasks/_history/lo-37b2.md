## Acceptance gate

**Gate**: parsing a ChatGPT answer containing web citations yields zero entries in
`metadata.images` for pill favicons.

Prose-only gate — verified by worker judgment, no script to run.


## The defect

Web-citation pills (`[data-testid="webpage-citation-pill"]`) live **inside**
`.markdown`, and each contains an `<img>` favicon. Verified live 2026-07-28: 8 pills
inside `.markdown`, each with 1 `<img>`.

`ChatGPTParser.extractImages()` collects every `<img>` in the turn, so each favicon
is filed as a conversation image and rendered as one in the exports.

Those favicon URLs are also third-party, so they re-introduce the leak `lo-8312`
closed for the Google favicon service — see `lo-31e6`, which owns reconciling the
privacy disclosures.

## Work

Scope image collection: exclude `<img>` inside citation pills, artifact/code panels
and `<button>`s. Enumerate what an `<img>` can legitimately mean on ChatGPT
(user upload, generated image, inline markdown image) and collect only those.

## Context

Same misclassification class as `lo-4b7f`, where an SVG artifact's decorative
preview image was collected as a conversation image and hung the PDF exporter
forever. Read that payload — if a single scoping rule fixes both, say so.

Read `docs/dev/parser-gotchas.md` §6.
