## Acceptance gate

**Gate**: pdf, docx and html read every font family, size, colour and spacing value
from ONE shared module; no exporter contains a bare typographic literal.

```bash
pnpm typecheck && pnpm test:run && pnpm build
```

## Why this task exists

The project owner (2026-07-28): *"I want that all our outputs are shown in a
similar way: similar font, similar spacing, etc. — of course just when possible."*

A cross-format audit found there is **no shared styling layer at all**. Every
exporter invents its own numbers: font sizes as raw `10`/`20`/`24`/`32`, colours as
raw RGB triples or hex strings, spacing as raw multipliers / rem / twips.

- `BaseExporter` (`src/core/exporters/base-exporter.ts:1-119`) carries ZERO
  typographic decisions — only i18n labels, timestamps, blob creation.
- `src/ui/themes/*.css` styled the popup only and was DELETED (`lo-ce4b`).
- `DOCXExportOptions` (`src/core/types/exporter.ts:59-66`) exposes only
  title/author/useHeadings. `PDFExportOptions` (`:27-43`) only pageSize/
  orientation/margins/pageNumbers/imageQuality. No font or colour knobs anywhere.

**This blocks `C-4` (font sizes) and `C-5` (pagination polish).** Without it, three
font sizes get wired into six independent sets of magic numbers.

## Divergences to reconcile (ranked by user-visible impact)

1. **Body text** — pdf Helvetica 10pt (`pdf-exporter.ts:1053-1055`) vs docx Arial
   12pt (`docx-exporter.ts:158-160`) vs html system-ui at browser default ~16px,
   line-height 1.6 (`html-exporter.ts:317-323`).
2. **Code blocks** — pdf 9pt Courier on a light-gray box with a language label
   (`pdf-exporter.ts:975-1012`); docx 10pt Courier New, no background or border
   (`docx-exporter.ts:425-457`); html a DARK GitHub-Dark themed `<pre>` with syntax
   highlighting (`html-exporter.ts:477-486`). The most drastic single divergence.
3. **Metadata block** — pdf and html add visual structure; docx just stacks plain
   paragraphs.
4. **Blockquote** — pdf italic + gray + rule; html italic + gray + border; docx
   border ONLY, no italic, no gray (`docx-exporter.ts:501-514`).
5. **List indent units** — mm (pdf) / twips (docx) / rem (html) / 2 spaces (md, txt).

Platform brand colours exist in pdf (`pdf-exporter.ts:944-951`) and html
(`html-exporter.ts:404-445`) with slightly different shades, and not at all in docx
— fold the canonical values into the token module (`C-3` then consumes them).

## Work

Create a style-tokens module: font stacks per role, a size scale, a colour palette
including the platform brand colours, and a spacing scale. Wire pdf + docx + html to
it **in the same change** — a token module only half-adopted is worse than none.

md and txt have no typographic surface; leave them alone beyond confirming their
structural conventions still line up.

Units differ per format by necessity (pt / half-points / twips / rem). Define tokens
in ONE canonical unit and convert at the exporter boundary — do not store four
parallel sets of numbers.

## Tests

- A test asserting each of pdf/docx/html sources its body font size and family from
  the token module (import the module in the test and assert the rendered output
  matches the token, so a drifted literal fails).
- A grep-style test failing on a bare numeric font-size literal in the three
  exporters.
