## Acceptance gate

**Gate**: when a message carries `metadata.research`, every registered exporter
renders it; proven by a test per format.

```bash
pnpm typecheck && pnpm test:run
```

## The defect

`ChatGPTParser.extractDeepResearchInfo` populates
`message.metadata.research` (duration, source count, search count). **No exporter
reads it.** Parsed, stored, dropped by all six formats.

Found by the completeness matrix in PR #52.

## Why it matters now

Deep Research support is being added per platform (`lo-f132` for ChatGPT). If a
parser routes any of it through `metadata.research`, the work is invisible in
every export. Gemini deliberately avoided this by merging its report into the
answer body and its sources into `metadata.webSearches` — both already rendered.

So decide first: is `metadata.research` worth rendering, or should it be removed
and the parsers routed through the shapes exporters already handle? **Either is a
valid outcome** — a field nothing renders is worse than no field. Record the
decision.

## Work

If rendering: add it to all six exporters in the same change (the repo's
recurring bug is a content type implemented in one format and missing in five).
If removing: delete the field, its parser call site, and its type.

## Tests

- One test per format, or a test asserting the field no longer exists.
- RED first.
