### Finding
The API is fetched with tree=True (all branches) and messages are paired to DOM turns purely by index after requiring human count == assistant count == DOM pair count. A conversation with an edited prompt, a regenerated answer, or an unanswered/aborted turn fails the equality and the export silently loses every artifact body and timestamp (only a warning), even though the API response carries uuids and parent links that could match exactly.

### Evidence
traced code path (node_modules absent, tests could not be run). Behaviour of tree=True returning non-active branches is from knowledge of the Claude web API, not observed here; CHANGELOG 1.3.0 itself mentions 'asymmetric threads (an unanswered turn, a regenerated one)' as real cases.

### Suggested direction
Walk the active branch from current_leaf_message_uuid via parent_message_uuid (or request the non-tree form), and match by message uuid/text rather than list position.
