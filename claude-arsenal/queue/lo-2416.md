# Payload: lo-2416 — D-6: every mechanical acceptance gate passes vacuously

**Gate**: every open task payload either carries a fenced ` ```bash ` / ` ```gate `
block under `## Acceptance gate`, or is explicitly marked prose-only; and a
deliberately-failing gate block is proven to make `release.sh done` refuse.

```bash
# Every open task's payload must either carry a fenced gate block or be
# explicitly marked prose-only. Exits non-zero listing any that does neither.
set -euo pipefail
bad=0
for id in $(python3 -c "
import json
for l in open('claude-arsenal/queue/tasks.jsonl'):
    l=l.strip()
    if not l: continue
    r=json.loads(l)
    if r['status'] in ('open','in_progress'): print(r['id'])
"); do
  f="claude-arsenal/queue/${id}.md"
  [ -f "$f" ] || continue
  if ! grep -qE '^\s*```(bash|sh|gate)' "$f" && ! grep -qi 'Prose-only gate' "$f"; then
    echo "ungated payload: $f"; bad=1
  fi
done
exit $bad
```

## What the spec requires

`claude-arsenal/AGENTS.md` states that `release.sh done` refuses to record `done`
unless "the payload's mechanical gate passes (it re-runs `gate_run.sh`, so the
evidence/bash gate is a hard precondition)", and that this "closes the false-`done`
hole".

## What the code actually does

`gate_run.sh` looks for the first fenced ` ```bash ` / ` ```sh ` block inside the
`## Acceptance gate` section (`gate_run.sh:65-66`). When no fenced block exists it
exits 0 without running anything (`gate_run.sh:61`).

**0 of 70 payloads in this queue contain a fenced block.** Every payload states its
gate either as prose or as an inline single-backtick command, which the regex does
not match. So:

- `gate_run.sh <id>` exits 0 for every task in this repo, having executed nothing.
- `release.sh done` re-runs it, gets 0, and treats the precondition as satisfied.
- The "hard precondition" that is supposed to close the false-`done` hole has been
  inert for all 27 tasks merged so far, and for every task still open.

Discovered by the `lo-194d` worker, which observed its gate would have "passed"
identically had it changed nothing. It ran the stated command by hand instead.

## Fix location

Two halves; both are needed.

1. **This repo's payloads** — `claude-arsenal/queue/*.md`. Convert the inline
   backtick command under `## Acceptance gate` into a fenced ` ```bash ` block for
   every payload whose gate is mechanically runnable. For payloads whose gate is
   genuinely a judgment call, add an explicit `_Prose-only gate — verified by worker
   judgment._` line so the absence of a block is visibly deliberate rather than an
   oversight.

2. **Upstream `claude-arsenal`** (`/home/ivant/dev/claude-arsenal`,
   `plugins/core/skills/init/assets/bin/gate_run.sh`) — a silent exit 0 on a
   missing block is the failure mode. It should distinguish "no gate section at
   all" from "a gate section that names a command but fences nothing", and at
   minimum print a loud `gate_run: no runnable block — NOT verified` on stderr so a
   vacuous pass is never mistaken for a real one. Consider an
   `ARSENAL_GATE_REQUIRE_BLOCK=1` mode that exits non-zero instead.

## Tests

- A deliberately-failing fenced gate block (`exit 1`) in a scratch payload must make
  both `gate_run.sh` and `release.sh done` refuse. Prove the choke point works at
  all before trusting it.
- After converting the payloads, re-run the audit: every open task either has a
  fenced block or the explicit prose-only marker.
