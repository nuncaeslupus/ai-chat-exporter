# SD-7: drift report strings in all seven locales — RETIRED, absorbed

**Status: retired. Do not implement this task.** Its work now lives in
`lo-8775` (SD-8) and `lo-e18b` (SD-9).

## Why

`tests/unit/extension/locales.test.ts` carries a check named *"declares no key
the extension never references"*: it scans `src/**/*.ts`, `popup.html` and
`manifest.base.json` and fails if a declared key is never used. **A
locale-only task is therefore structurally unable to pass the gate** — the keys
are orphans until the UI that uses them lands, and that UI depended on this
task.

The SD-7 worker diagnosed this correctly and produced the evidence: PR #142's
`noConversationFoundTitle` / `noConversationFoundMessage` keys were added in the
same commit as their popup usage. That is the codebase's actual convention, and
splitting locale keys into their own task contradicted it. The error was in the
plan, not the implementation.

## Resolution

Locale keys land with the code that references them:

- **`lo-8775` (SD-8)** adds the 7 keys its markup references: `driftRowTitle`,
  `driftRowDetail`, `driftRowAction`, `driftReportTitle`, `driftReportIntro`,
  `driftReportCopy`, `driftReportCopyAndReport`.
- **`lo-e18b` (SD-9)** adds the 3 keys it references from `popup.ts`:
  `driftReportCopied`, `driftReportCopyFailed`, `driftReportLoading`.

`driftReportDismiss` is **dropped**. The plan listed a key for a dismiss control
it never actually specified — the behaviour table suppresses on copy, and there
is no dismiss button. A key for a control that does not exist would be a
permanent orphan and would fail the same check.

The exact JSON for all seven bundles is in
`docs/superpowers/plans/2026-07-29-selector-drift-popup-surfaces.md`, Task 4;
take the relevant subset for each task.

## Acceptance gate

None — this task is retired and delivers nothing.
