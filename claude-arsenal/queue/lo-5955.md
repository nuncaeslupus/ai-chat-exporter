# D-33: re-land the Deep Research HTML fidelity work, with a guard

`lo-b4cd` / #196 relayed sanitized HTML so Deep Research reports would gain real
headings and tables. **It was reverted in #198 because it lost the entire report
body on a real page.**

## What happened

Before #196 (capture fix #194 only), the owner's export contained the full report
— roughly 170 lines: executive summary, every section, three case studies. Ugly
(flat paragraphs, tab-separated tables) but complete.

After #196 the whole answer collapsed to a single line of chrome:

```
Research completed in 8m · citations · searchesUso de mangueras de agua en incendios grandes
```

Header text plus the widget title, concatenated. **No body at all.** Also absent:
the promised `[Deep Research: 8m, 18 sources, 60 searches]` marker, and the counts
were still missing from `· citations · searches` — so the `extractDeepResearchInfo`
wiring was not producing its marker either.

## Why the tests passed anyway — fix this first

#196 added `tests/unit/core/services/deep-research-html-fidelity.test.ts` driving
a **synthetic** fixture (duplicate title, odometer digits, a table, an SVG) through
the pipeline. Every assertion checked that an **artifact was removed**. Not one
checked that **real body content survives**.

A fixture built to exercise cleanup cannot detect cleanup that removes too much.
That is the whole lesson of this task.

**Write the guard before re-attempting the feature:**
- A fixture resembling a *real* report — multiple `<h2>`/`<h3>` sections, several
  paragraphs of prose, a table, a list — must survive the full path with its
  **substantive text intact**. Assert on specific sentences from the body, and on
  a floor for total body length, not just on absence of artifacts.
- Prove it is not vacuous: it must FAIL against #196's reverted implementation.
  Recover that code with `git show e7bfca5` (the squashed commit) or
  `git show <revert>^`. Say in the PR that you ran this and what failed.

## Then re-land, and diagnose before rewriting

The reverted diff is available — **work out why the body was dropped rather than
rewriting blind.** Prime suspects, in order:

1. **The sanitizer's allowlist.** If the report body sits in elements
   `sanitize-html.ts` drops (custom tags, unusual wrappers), sanitizing yields
   only the chrome that happens to use plain tags. Check what survives for a
   realistic body.
2. **Wrong capture root.** `#196` may have serialized a container that holds only
   the header, while the body lives in a sibling/descendant it never reached.
   Note the shell frame's body is 5 chars and the real content is in the nested
   `about:blank` `#root` iframe (that part, from #194, works).
3. **The cleanup helpers over-reaching** on real markup in ways the synthetic
   fixture did not exercise.
4. **The 600,000-char HTML bound** silently rejecting a real report and falling
   back to a text path that then also failed.

Log or assert on the captured length at each stage so a future failure is
diagnosable rather than silent.

## Non-negotiable

- **Never lose content to gain formatting.** If the HTML path yields materially
  less text than the text path would, **use the text path** — ugly and complete
  beats pretty and empty. Implement that as an actual runtime comparison, not an
  aspiration.
- Layered fallback: HTML → text relay → honest placeholder. Never a partial report
  presented as complete.
- Keep #194's nested-frame capture intact; it survived the revert and works.

## Worth keeping from #196

These were good and should return:
- Routing captured HTML through `ConversationStructureService` /
  `HtmlContentParser` — the right architecture.
- Wiring `extractDeepResearchInfo` into the widget-only-turn branch to recover the
  real counts (a genuine pre-existing gap) — but verify the marker actually
  reaches the export this time; it did not in #196.
- The **scoped** dedupe (heading-only survivor + `tr`/`tbody`/`thead`/`table`/
  `ul`/`ol`/`dl` skipped) and the **size-thresholded** diagram marker (80px, with
  `viewBox` fallback and strip-silently when no size info). Both were verified
  non-vacuous — keep them and their four negative tests.

State plainly in the PR that live verification is outstanding, with exact steps.
