# Payload: lo-c418 — CRITICAL: ChatGPT parser extracts nothing from a live page

## Acceptance gate

**Gate**: parsing `tests/fixtures/dom-snapshots/chatgpt/formatting-showcase-2026-07.html`
yields 1 correctly-paired Q&A with non-empty user and assistant content; the turn

Prose-only gate — verified by worker judgment, no script to run.

selectors come from the `SelectorSet`, not from inlined strings.

## The defect

Verified live on chatgpt.com 2026-07-28 (`gpt-5-5`).

ChatGPT renamed the turn wrapper from `<article data-turn="...">` to
`<section data-turn="...">`. Measured on a live conversation:

- `main article` → **0**
- `article[data-turn="user"]` → **0**
- `article[data-turn="assistant"]` → **0**
- `section[data-turn]` → 2
- `[data-testid^="conversation-turn-"]` → 4 (all `SECTION`)

`src/core/parsers/chatgpt/parser.ts:151` and `:217` **hardcode**
`article[data-turn="user"]` / `article[data-turn="assistant"]`, so
`extractUserMessages()` and `extractAssistantMessages()` both return empty and the
parser produces an empty conversation — silently, with no error.

Every unit test still passes: they run against a 2026-01 fixture that still has
`<article>`. That is why this went unnoticed.

## Work

1. Make the turn selectors **tag-agnostic** — match on the stable attribute
   (`[data-turn="user"]`, or `[data-testid^="conversation-turn-"]`), not the tag.
   `data-turn` and `data-message-author-role` both survived the migration; the tag
   name and the Tailwind classes did not.
2. Read them from `CHATGPT_SELECTORS.custom`, do not inline (that is `lo-4cdc`, but
   fixing the inlining is unavoidable here — coordinate, do not duplicate).
3. Add a regression test against the new fixture.

Read `docs/dev/parser-gotchas.md` §1 and §2 first.
