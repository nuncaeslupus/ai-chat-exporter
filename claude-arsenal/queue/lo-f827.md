# Payload: the web-search marker duplicates the Sources section

## Acceptance gate

**Gate**: a message with web-search results renders the sources **once** per
format — no bare `[Web Search: …]` marker above a full Sources section.

```bash
pnpm lint && pnpm typecheck && pnpm test:run
```

## The defect

Found by `lo-23fb` (PR #112), visible in its own pdf test output:

```
[Web Search: lighthouse keeper shortage]
Web Search Results: lighthouse keeper shortage
```

`ConversationStructureService.convertMessage` pushes the `[Web Search: …]` marker
paragraph **unconditionally**, and then every exporter renders a full section for
the same search.

## The fix already exists six lines away

The `artifacts` branch in the same function solves exactly this: it skips the
marker when a fuller rendering exists downstream (`if (artifact.content) continue;`).
`webSearches` needs the same guard on `search.results?.length`.

Confirm against html and pdf, which render the section even for a search with no
results — the marker is the only output in that case and must survive.

## Tests

Per format: a search **with** results renders the section and no marker; a search
**without** results still renders the marker.

## Location

`src/core/services/conversation-structure-service.ts`, exporter tests.
