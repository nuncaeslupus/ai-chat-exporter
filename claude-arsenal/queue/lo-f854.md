# Payload: lo-f854 — Print is popup-blocked and leaks

**Gate**: printing on a large conversation either opens the print view or tells the user why not; no object URL is left unrevoked.

`src/extension/content/content-script.ts:266` and `:288` call `window.open()` after several `await`s (re-parse, Claude API fetch, export generation). By then the user-gesture window has closed, so browsers block the popup. When `printWindow` is `null` the code neither revokes the object URL (leak) nor tells the user anything — print silently does nothing.

Fix direction: open the window synchronously on the click and fill it once content is ready, or fall back to an in-page print. Either way, handle the `null` return: revoke the URL and surface a message.
