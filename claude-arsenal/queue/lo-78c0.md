# Payload: every chevron in the popup is below the non-text contrast bar

## Acceptance gate

**Gate**: every chevron clears 3:1 against its background, and each one is
asserted in `tests/unit/accessibility/contrast.test.ts`.

```bash
pnpm lint && pnpm typecheck && pnpm test:run
```

## The defect

Found by the R5 worker (`lo-1789`, PR #120). `--color-text-muted` measures
**2.54:1** on the surfaces it is used on — under even the 3:1 bar for non-text
graphics. It is the fill for `.setting-row-chevron`, the format-menu chevrons and
the submenu navigation chevrons, and **none of them are asserted**, which is why
the contrast suite never caught it.

Pre-existing, not introduced by the redesign. The R5 worker matched the existing
token rather than diverging one view, and dropped its own chevron assertion
instead of shipping a value the rest of the popup contradicts — the right call for
that task, and the reason this one exists.

## Work

1. Find every chevron/arrow/glyph using `--color-text-muted` and the surface each
   sits on.
2. Either darken the token or split it: a `--color-glyph` for non-text marks that
   clears 3:1, leaving `--color-text-muted` for the separator dots its comment
   designates it for. Prefer darkening if nothing else depends on the light value.
3. Assert every one of them, so this cannot regress silently.

Twelve spec colours have already been substituted for failing this gate; this is
the same family — light greys on light surfaces. Consider whether the design's
whole tertiary tier wants revisiting rather than patching each site, and say so in
the outcome if you think it does.

## Location

`src/extension/popup/popup.css`, `tests/unit/accessibility/contrast.test.ts`.
