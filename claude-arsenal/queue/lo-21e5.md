# D-30: txt never wraps artifact content to 72 columns

Raised by the repo owner 2026-07-30: "TXT cuts lines at 72, I think, but not in
artifacts like MD Deep Researches. It may be the expected behavior."

**It is not expected — it is an oversight.** Confirmed in the code:

- `src/core/exporters/txt-exporter.ts:28` — `const TXT_WIDTH = 72`
- Line ~110–117 — the wrap helper, "Wrap prose to `TXT_WIDTH`, never splitting a
  word", used for message prose.
- **Line ~199 — `lines.push(artifact.content || '')`**, pushing artifact content
  **raw and unwrapped**, bypassing that helper entirely.

So a Deep Research report in a `.txt` export is one enormous line per paragraph,
in a format whose entire R-5 premise is a 72-column layout.

## The rule to implement

Wrap **prose** artifacts; leave **code** artifacts alone. Hard-wrapping source
code at 72 columns would corrupt it, and wrapping a markdown table would break
it.

This distinction already exists — use the shared `isProseArtifact` helper in
`src/core/exporters/artifact-content.ts` (added by A-1 / #184) rather than
inventing a second predicate. `type === 'document'` is prose; everything else,
including a `code` artifact whose language happens to be markdown, is not.

Within a prose artifact, do not wrap lines that must stay intact: fenced code
blocks, table rows, and indented code. Wrap paragraph text only.

## Acceptance gate

A `type: 'document'` artifact's prose is wrapped at 72 columns in the txt export;
a `type: 'code'` artifact's content is byte-identical to its input.

```bash
pnpm test:run tests/unit/core/exporters/txt-exporter.ts tests/unit/core/exporters/claude-artifact-types-formats.test.ts
```

## Tests
`claude-artifact-types-formats.test.ts` already drives every artifact type through
all six formats — add there: no line in a prose artifact's txt output exceeds 72
characters, and a code artifact's content round-trips unchanged. Include a case
with a fenced code block inside a prose artifact, asserting the fenced lines are
NOT wrapped.
