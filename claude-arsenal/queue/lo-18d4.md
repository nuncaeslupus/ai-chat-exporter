# Payload: lo-18d4 — R7: secondary states

**Spec: `docs/design/popup-redesign.md` § "6. Estados secundarios"**.

## Acceptance gate

**Gate**: all five secondary states render inside the same 260 px body with the
spec's colours and copy, and each is reachable from the real condition that
produces it — not only from a test hook.

```bash
pnpm lint && pnpm typecheck && pnpm test:run && pnpm build
```

## The five states

1. **Detecting** — skeleton bars, inert button, `Detectando…` pill.
2. **No selection** — export disabled; the `Contenido` row becomes an amber
   warning with a `Elegir pares` action.
3. **Exported with warnings** — amber card, `Guardado, pero incompleto`,
   `Reintentar`, main button becomes `Exportar de nuevo`. Full reason stays in
   the `title` attribute, as `popup.ts` already does with `response.warning`.
4. **Unsupported page** — dimmed header, and three platform links **generated
   from `parserRegistry`** (the spec is explicit: no duplicated hardcoded list),
   opened with `chrome.tabs.create`.
5. **Reload needed** — amber circle, `Recargar la página` button wired to
   `chrome.tabs.reload`, plus the `Ctrl` `R` hint.

## Tests

jsdom: each state renders its distinctive element and no other; the platform
link list is derived from `parserRegistry` (add a fourth fake platform in the
test and assert a fourth link appears); the reload button calls
`chrome.tabs.reload`; export is disabled exactly when nothing is selected.
