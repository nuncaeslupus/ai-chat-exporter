# D-39: `ParseResult.warnings` is written by every parser and read by nobody

Split out of `lo-41c9` (PAR-1, merged as #207). The PAR-1 worker confirmed the
finding is real but could not fix it: the consumer side lives in
`src/extension/content/content-script.ts`, which a concurrent worker owned at the
time. It correctly left the boundary alone rather than racing.

## The defect

All three parsers populate `ParseResult.warnings`. Nothing ever reads it, so any
warning a parser raises is silently discarded — the parser's own signal that
something looked wrong never reaches the user.

This matters more now than when it was found: #207 armed two drift rules that had
never fired before (`turns-dropped` and `content-shortfall`), so parsers now have
genuinely useful things to say.

## The fix

Route `ParseResult.warnings` into the surface the popup already has. Do **not**
invent a new channel:

- EXP-2 (#204) added an optional `warning` to `ExportResult` and a merge of
  `result.warning` in `content-script.ts`'s `handleExport`/`handlePrint`.
- TYPE-1 may have extended the same path for failures — **rebase on current `main`
  and read what exists before adding anything.**
- The popup renders warnings via `showWarning()`.

Respect the distinction TYPE-1 established: a **warning** means "it worked but
something may be off"; a **failure** means "no usable output". Parser warnings are
warnings.

If several warnings arrive at once, decide how they combine (the popup box is a
fixed 436x396 and the owner has been through four rounds of spacing work — do not
overflow it). Long detail belongs somewhere that scrolls, not in the header pill.

Warning text shown to the user must be **localised** — add keys to all 7
`_locales/*/messages.json`. Note `tests/unit/extension/locales.test.ts` fails on a
declared key that nothing references, so keys land with their consumers.

## Acceptance gate

A parser warning reaches the popup and is visible to the user, localised, without
breaking the fixed popup box.

```bash
pnpm test:run && pnpm lint && pnpm format:check && pnpm typecheck
```

## Tests
Assert end-to-end that a parse producing a warning results in the popup showing it —
assert on the response and the DOM, not on a mock having been called. Prove the test
fails before the fix.

## Location
`src/extension/content/content-script.ts`, `src/extension/popup/popup.ts`,
`_locales/*/messages.json`
