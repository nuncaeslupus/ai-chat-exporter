# Payload: lo-880d — `includeTimestamps` is a no-op in 5 of 6 formats

## Acceptance gate

**Gate**: with `includeTimestamps: true`, a per-message timestamp appears in every
registered format; with `false`, it appears in none.

```bash
pnpm typecheck && pnpm test:run
```

## The defect

`ExportOptions.includeTimestamps` (`src/core/types/exporter.ts:86`, default `true`
at `:99`) is read by exactly **one** exporter:

```
$ grep -rn "includeTimestamps" src/core/exporters/
src/core/exporters/json-exporter.ts:126:    if (options.includeTimestamps) {
```

`structured-md`, `txt`, `html`, `docx` and `pdf` have **no per-message timestamp
rendering at all** — there is nothing for the flag to gate. Found by the `lo-f096`
worker (PR #81) while wiring the popup toggles.

## Why this is now urgent

PR #81 shipped a user-facing **"include timestamps" checkbox in the popup**. The
owner chose to ship it and close this gap immediately rather than hide the
control. Until this task lands, toggling that checkbox visibly does nothing in 5
of the 6 formats — a control that appears broken.

`includeMetadata` is fine: all six honor it except `json-exporter.ts`, which
always writes `title`/`platform`/`url`/`model`/`createdAt` regardless — see the
separate finding below.

## Work

Render a per-message timestamp in `structured-md`, `txt`, `html`, `docx` and
`pdf`, gated on `options.includeTimestamps`.

`BaseExporter` already provides `formatTimestamp()` — use it rather than
inventing per-format date formatting. `Message.timestamp` is **optional**, so
handle its absence without emitting an empty label or the string `undefined`.

**Consistency is the point of this task, not a nice-to-have.** The project owner
has asked that all formats render the same conversation the same way. Decide ONE
placement and ONE format for the timestamp, apply it to all five, and state the
decision in the PR body. The obvious candidate is alongside the existing role
label ("User" / assistant name), which every format already renders — see
`pdf-exporter.ts:242-246`, `docx-exporter.ts:179-197`,
`html-exporter.ts:420-445`, `structured-md-exporter.ts:76,81`,
`txt-exporter.ts:101,106`.

## Also fix, same change (it is the mirror-image bug)

`json-exporter.ts` **ignores `includeMetadata`** — it always writes
`title`/`platform`/`url`/`model`/`createdAt` and never checks the option. Gate
them, so both flags mean the same thing in all six formats.

## Tests

- One test per format asserting a timestamp is present when the flag is on and
  absent when off — six formats, twelve assertions. RED first.
- One test asserting a message with **no** `timestamp` does not emit a stray
  label or `undefined` in any format.
- One test asserting `json-exporter` omits `title`/`platform`/`url`/`model`/
  `createdAt` when `includeMetadata` is `false`.
