# Payload: lo-83c3 — C-2: heading levels map inconsistently across formats

**Gate**: a source heading of level N renders at the same relative level in every
format.

```bash
pnpm typecheck && pnpm test:run
```

## The defect

Each format shifts heading levels differently, so the same heading lands at a
different visual level per format:

| Format | Mapping | Location |
| --- | --- | --- |
| html | `level + 2`, capped 6 | `html-exporter.ts:191` |
| md | `level + 3`, capped 6 | `structured-md-exporter.ts:178` |
| pdf | `max(16 - level, 11)` pt | `pdf-exporter.ts:524` |
| docx | `HEADING_3`..`HEADING_6` | `docx-exporter.ts:399-407` |

## Work

Pick ONE canonical mapping and apply it everywhere. Note the offsets are not
arbitrary — the exported document already uses the top levels for the conversation
title and the role labels, so body headings must sit below those. Establish what
level the title and role label occupy in each format first, then derive the body
offset from that rather than picking a number.

Depends on `C-1` (the token layer) — take the heading size scale from there.

## Tests

One test per format asserting a level-1 and a level-3 source heading land at the
agreed levels. RED first.
