# Payload: lo-e836 — C-5: orphans, widows, keep-with-next and split tables

**Gate**: no role label is stranded alone at the foot of a page; no table row splits
across a page break in docx.

```bash
pnpm typecheck && pnpm test:run
```

## The request

The project owner (2026-07-28): *"usual editing tools, like not having dead lines or
broken tables when possible."*

## What the audit found

**docx sets NOTHING.** Zero occurrences of `pageBreak`, `keepNext`, `keepLines`,
`cantSplit` or `widowControl` anywhere in `docx-exporter.ts`:
- `TableRow` (`:558,574`) has no `cantSplit`, so Word's default applies and rows
  CAN split mid-row across a page boundary.
- Role headings (`:179-197`) have no `keepNext`, so a role label can strand at the
  foot of a page with its content overleaf.

**pdf is ad-hoc.** Manual y-coordinate checks with FOUR different thresholds:
`lineHeight*10` before a Q&A pair (`:171`), `*3` before a block (`:271`), `*5`
before artifacts (`:339,418`), and an exact bottom check per wrapped line
(`:531,594,782,1019,1060`).
- No orphan/widow control — each wrapped line is placed independently
  (`:1058-1066`), so a single line can strand.
- No keep-with-next — the role label (`:242-246`) has NO page-break check before it
  at all.
- Table rows never split mid-row (`:853,895`), but a header can land alone at the
  foot of a page with no body rows following.

**html is the only format with print control** — a `@media print` block
(`html-exporter.ts:743-811`) setting `break-inside: avoid` on `.header`, `.qa-pair`,
`.message`, `pre`, `blockquote`, `table`, `ul`, `ol`. It applies ONLY when the HTML
is printed through a browser; it has no bearing on the jsPDF or docx paths.

## Work

- **docx**: set `keepNext` on role labels and headings, `keepLines` where a block
  must not fragment, and `cantSplit` on table rows. These are one-line properties
  the `docx` library already supports — this is the cheap half.
- **pdf**: replace the four ad-hoc thresholds with one "will this block fit"
  helper, and give the role label a page-break check so it cannot strand. Real
  orphan/widow control needs measuring the wrapped line count before committing to
  a page — do that for paragraphs at minimum.
- Depends on `C-1` for the spacing/line-height tokens the measurements read.

## Tests

- docx: unzip and assert `w:keepNext` on role labels and `w:cantSplit` on table rows.
- pdf: build a fixture engineered to place a role label at a page boundary and
  assert the label and its first content line land on the SAME page.
