# P-5: popup spacing overhaul

Author feedback, 2026-07-30, after living with #183 (P-1/P-2/P-3) and #187 (P-4).
The direction is explicit:

> "In general, let's try to put some order in the popup spacing. Maybe we need to
> do it taller and redistribute spaces better."

Treat this as **one holistic pass over the popup's spacing system**, not five
independent tweaks. The previous round moved individual numbers; this one is
supposed to leave a coherent rhythm behind.

## The five specific asks

1. **More horizontal inset still.** `--pad-x` is currently **22px** (raised from
   18px in #183) and the owner wants "a little more". Change it **at the token**;
   it is already plumbed everywhere, so this should be a one-line change plus a
   width adjustment.

2. **More vertical room for the privacy line** — "Se genera en tu navegador. Nada
   se envía a ningún servidor." It is cramped. Give it real breathing space above
   and below.

3. **Even more space between the chevrons and the right border.** #183 put every
   navigable row's chevron at a uniform 10px inside its row (measured: 32px from
   the popup edge = 22px `--pad-x` + 10px). The owner wants more. Keep all
   navigable rows in agreement — Contenido, Opciones **and** Nombre del archivo.

4. **The Options submenu looks wrong.** Owner's words: "things are not well
   left-aligned and there is no correct vertical spacing to understand what is
   part of what." Two distinct problems:
   - **Alignment**: controls/labels in the Options list do not share a left edge.
     Establish one and hold every row to it.
   - **Grouping**: vertical spacing does not communicate hierarchy, so a label and
     the control it governs do not read as belonging together. Use spacing to
     group (tight within a setting, looser between settings) rather than uniform
     gaps everywhere.

5. **The box may get taller.** The design's fixed `56 + 320` body height is
   **explicitly relaxed by the owner** for this task. Growing
   `--popup-width` further is also allowed (Chrome's ceiling is 800px; it is at
   428px).

## Binding constraints

- **The popup must still never change size between states.** "Taller" means a new
  fixed height, not a height that varies by view. Every view — main, Contenido,
  Opciones, Nombre del archivo, settings/gear, drift report, and the secondary
  states (detecting, no selection, unsupported, reload) — must fit the same box.
  **Check the tall ones**, especially the pair chooser and the drift report; a
  taller box that clips the drift report is a regression.
- **Do it at the tokens.** Introduce vertical spacing tokens if none exist, the
  way `--pad-x` handled the horizontal axis. Hardcoded pixel values scattered
  across rules are what made this a second round of work.
- Scroll areas must keep the slim tokenized scrollbar from P-3 — **all eight**
  (`.view-scroll`, `.format-menu-list`, `.qa-selection-list`, `.options-list`,
  `.filename-body`, `.drift-report-body`, `.drift-report-preview`, and the
  settings view). `.drift-report-preview` was missed once already.
- Contrast tokens must stay tokenized; `tests/unit/accessibility/contrast.test.ts`
  is a real gate.

## Verify it rendered, not just that tests pass

The tests cannot see spacing. **Build the extension and look at every view**, in
both light and dark, at the final size:

```bash
pnpm build:chrome
```

Then load `dist/chrome` unpacked, or serve `dist/chrome/popup/popup.html` over
`python3 -m http.server` and inspect with `getComputedStyle`. Report the final
`--popup-width`, `--pad-x`, the box height, and the chevron inset you settled on.

**Known limitation:** the popup opens in its "detecting" state and the main-view
rows do not render without the Chrome APIs, so main-view rows cannot be measured
from a plain page load — toggle views directly, or load it unpacked as a real
extension.

## Acceptance gate

Every view fits one fixed box with no clipping and no horizontal overflow; the
Options submenu shares a single left edge and groups related rows by spacing.

```bash
pnpm test:run tests/unit/extension/popup/ tests/unit/accessibility/contrast.test.ts
```

These are visual changes — do **not** invent brittle pixel assertions. Assert
token values only where a value is genuinely load-bearing.

## Location
`src/extension/popup/popup.css`, and `popup.html` if the Options submenu's markup
is what prevents a shared left edge.
