# Payload: lo-e339 — Context menu ignores `chrome.runtime.lastError`

## Acceptance gate

**Gate**: a context-menu action on a tab with no content script surfaces an error instead of doing nothing.


Prose-only gate — verified by worker judgment, no script to run.

`src/extension/background/service-worker.ts:266` — `chrome.tabs.sendMessage` is called fire-and-forget with no callback and no `chrome.runtime.lastError` check. When the content script is not present (tab loaded before install, extension reloaded, unsupported page), the message fails and nothing happens, with no diagnostic anywhere.

Fix: check `lastError` and surface it through the same error path built in `lo-2086`.

## Same root cause as `lo-db20` — do not fix it twice

`lo-db20` is the popup's version of this exact bug: `chrome.tabs.sendMessage` to a
tab with no content script. Both surfaces need the same thing — try the message,
and if nothing is listening either inject the script and retry or surface a real
error. That belongs in **one** helper both callers use, not two guards.

`lo-db20` runs first and owns the decision (including whether the `scripting`
permission is added). This task applies the resulting helper to the background's
fire-and-forget call sites and adds the context-menu error surfacing.
