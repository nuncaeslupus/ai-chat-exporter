## Part 2 — the Claude parser's favicon path is unaudited

`src/core/parsers/claude/parser.ts:519-526` reads a citation favicon straight off
the source page's DOM (`faviconImg?.getAttribute('src')`) and stores it verbatim.
`src/core/exporters/html-exporter.ts:169` then writes it into the export as
`<img src="…">`.

If claude.ai serves those favicons from an absolute third-party URL, **Claude
exports still phone out when opened** — the same defect `lo-8312` fixed for
ChatGPT, on a path that task did not cover.

**This is unverified, not confirmed.** `tests/fixtures/dom-snapshots/claude/real-capture.html`
contains no citations with favicons, so there was no evidence either way at the
time of writing. Establish the fact before fixing:

1. Capture a Claude conversation that actually contains web-search citations.
2. Inspect what `faviconImg.getAttribute('src')` yields — absolute third-party
   URL, same-origin path, or a `data:` URI.
3. If it is third-party, apply the same resolution `lo-8312` chose (drop it) and
   extend that task's test to cover the Claude parser too. If it is not, say so

has no favicon handling, but `lo-4d4a`'s in-flight work may add some.
