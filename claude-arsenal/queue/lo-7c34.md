# Payload: lo-7c34 — Image re-encoding on every parse

## Acceptance gate

**Gate**: exporting a conversation with many images twice does the canvas work at most once per image.


Prose-only gate — verified by worker judgment, no script to run.

`src/core/parsers/claude/parser.ts:271-300` (`tryGetImageDataUrl`) draws each image to a canvas and calls `toDataURL('image/png')` synchronously, for every image in every user turn. `content-script.ts` re-runs `parser.parse()` on every `export_conversation`, `print_conversation` **and** `get_conversation` message — so opening the popup alone pays the full cost. A conversation with 50 uploads means 50 synchronous canvas encodes per click, each holding a base64 copy (~33 % larger than the source) in message metadata.

Fix direction: cache by image src, and/or defer encoding until an exporter actually needs embedded image data — the popup's `get_conversation` never does.
