# Payload: lo-0e58 — D-10: the HTML syntax highlighter corrupts every code block

## Acceptance gate

**Gate**: a code block containing a keyword AND a quoted string renders as
well-formed, correctly-nested markup in the HTML export.

```bash
pnpm typecheck && pnpm test:run
```

## The defect

`src/core/exporters/html-exporter.ts`, `generateSyntaxHighlightingScript()`
(~lines 818-887). The regex chain applies keyword highlighting FIRST, injecting
`<span class="hljs-keyword">…</span>`. A LATER "strings" regex then re-matches the
quoted `"hljs-keyword"` attribute value it just wrote, wrapping markup it produced
itself.

Verified by the `lo-8d36` worker: `function foo() { return 1; }` renders as

    <span class="<span">"hljs-keyword"</span>&gt;function foo() { …

Every HTML export containing a code block with a matched keyword is affected.

## Work

Highlight in ONE pass with a combined tokenizer, or mask/escape already-emitted
spans before the string pass. Do not add a highlighting dependency — the export
must stay self-contained with no remote subresource (pinned by test since PR #54).

## Tests

`tests/unit/core/exporters/html-exporter.test.ts` currently AVOIDS asserting on the
injected keyword-span markup and carries a comment pointing at this bug — remove
that avoidance and assert properly. Run the emitted script in jsdom (the existing
test already does this) and assert the resulting DOM has no `<span>` inside a
`class` attribute value, plus correct `hljs-keyword`/`hljs-string` classes.
RED first.
