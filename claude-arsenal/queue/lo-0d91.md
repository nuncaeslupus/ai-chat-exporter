# D-32: body headings land at `####`, so titles do not read as titles

Author feedback 2026-07-31: **"titles doesn't look like titles"**. Measured, not
inferred.

## What the spec requires

`docs/superpowers/specs/2026-07-29-exporters-redesign-design.md`, § *Heading
levels*:

> The role label stops being a heading. `DOC_HEADING_LEVEL.roleLabel` is removed
> and `bodyHeadingLevel`'s offset drops from +2 to +1: only level 1 (the
> conversation title) stays occupied, so **body headings start at level 2 — `##`
> in Markdown**, as the design specifies.

## What the code does

`src/core/exporters/style-tokens.ts`:

```ts
export function bodyHeadingLevel(sourceLevel: number): number {
  const source = Math.max(sourceLevel, 1);
  return Math.min(source + DOC_HEADING_LEVEL.title, DOC_HEADING_LEVEL.max);
}
```

A pure **absolute +1 offset**. So body headings only start at `##` when the
source's shallowest heading is `h1`. ChatGPT emits `<h3>` for an answer's section
headings, so they become `####`.

**Measured** on a real export the owner produced
(`Firefighting-with-Water-Hoses_2026-07-31 (4).md`) — the heading levels present
in the whole file:

```
1 x "# "     <- conversation title
7 x "#### "  <- every body heading
```

`##` and `###` are entirely unused. The document's whole visual hierarchy is
squeezed into the weakest available level, which is precisely the reported
symptom. The spec's stated intent — body headings *start* at level 2 — is
violated.

## The fix: normalise, don't offset

Map the heading levels **actually present** onto consecutive document levels
starting at `DOC_HEADING_LEVEL.title + 1` (= 2), preserving relative hierarchy.
With a source using h3/h4: h3 -> `##`, h4 -> `###`.

Decisions to make explicitly, and state them in the PR:

- **Scope: normalise per conversation, not per message.** Different answers may
  use different source levels; normalising per message would give two answers in
  one document different heading scales. Use the shallowest heading found across
  the exported body content so every answer shares one scale.
- **Gaps:** rank the *distinct* levels present and assign consecutive document
  levels, so a source using h2 and h4 (skipping h3) yields `##` and `###` rather
  than `##` and `####`. Do not preserve empty gaps — they are what produces the
  weak rendering.
- Keep the clamp at `DOC_HEADING_LEVEL.max`.
- `bodyHeadingLevel` currently takes only `sourceLevel`, so normalisation needs
  the set of levels present. **Do not** thread global mutable state through the
  exporters; compute the mapping once per export and pass it down, or derive it
  in the structure layer.

## Applies to every format with a heading surface

- **md** — `structured-md-exporter.ts:238`
- **html**, **docx**, **pdf** — all consume `bodyHeadingLevel`
- **txt** — has no heading levels but collapses headings to three underline
  styles (R-5); it must use the same *relative* ranking so its underlines match.
- **json** — passes source markup through losslessly. **Do not change json.**
