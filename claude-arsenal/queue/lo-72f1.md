# Payload: lo-72f1 — Store listings make privacy claims the code does not honour

**Gate**: a reachable privacy policy exists, and every privacy claim in both listings is true of the shipped code.

## Three confirmed problems

1. **The privacy policy 404s.** `docs/store-listings/chrome-web-store-v1.1.0.txt:123` points users to `https://github.com/ivansaul/ai-chat-exporter/blob/main/docs/PRIVACY.md`. Verified: **HTTP 404**. The owner is wrong (`ivansaul`, not `nuncaeslupus`) and no `PRIVACY.md` exists anywhere in the repo. Both v1.1.1 listings have a PRIVACY POLICY section.
2. **"No External Servers - No data leaves your computer"** (`chrome-web-store-v1.1.1.txt:85`, and `firefox-addons-v1.1.1.txt:100,103`) is not accurate as written:
   - `src/extension/background/service-worker.ts:91` fetches `https://claude.ai/api/organizations/.../chat_conversations/...` with `credentials: 'include'` — the user's session cookies, to Claude's private API. It is the user's own data going to the user's own account, which is defensible — but it is a network request the listing says does not happen.
   - `src/core/parsers/chatgpt/parser.ts:679` builds `https://www.google.com/s2/favicons?domain=...` URLs (see `lo-8312`).
3. **Gemini is advertised as working** in `docs/store-listings/firefox-addons-v1.1.1.txt:71` while the parser is unregistered and unreachable.

## Work

Write a real `PRIVACY.md`, host it at a URL that resolves, and correct both listings: describe the claude.ai API call and what it is for, drop or qualify the absolute "nothing leaves your computer" phrasing, and remove the Gemini claim until it ships.

## Context

This is the highest-consequence finding in the audit — not because it breaks the product, but because inaccurate privacy claims plus a dead policy link are exactly what gets an extension pulled from a store. It affects the **already-published** v1.1.1, so it is not gated on any other task.
