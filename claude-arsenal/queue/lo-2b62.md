# Payload: lo-2b62 — Coverage thresholds are fiction

**Gate**: `pnpm test:coverage` fails when coverage drops below the configured floor, and CI runs it.

## The bug

`vitest.config.ts:15-22` nests the thresholds under a `global` key:

```
thresholds: { global: { statements: 80, ... } }
```

Vitest 3's `CoverageThreshold` has no `global` key — thresholds are flat or per-glob. The whole object is silently ignored. Measured reality: **28.08 % statement coverage, exit code 0**.

Compounding: `package.json` `validate` never invokes `test:coverage`, and neither does `.github/workflows/ci.yml`. So even a correct threshold would gate nothing.

## Work

1. Flatten to `thresholds: { statements: N, branches: N, functions: N, lines: N }`.
2. Pick a floor that reflects reality and ratchets up — 80 would fail instantly at 28. Set it just under current, then raise it as the other testing tasks land.
3. Wire coverage into CI.
4. Decide deliberately whether `coverage.include: ['src/core/**/*.ts']` should stay — it currently makes ~2,900 lines of `src/extension/**` and `src/ui/**` invisible to the metric rather than merely untested.

## Context

Ordering: land this before the other testing tasks so their progress is measurable, but set the floor from the measured number, not aspirationally — a threshold that fails on arrival gets deleted by the next person in a hurry.
