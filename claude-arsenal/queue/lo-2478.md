# Payload: lo-2478 — Claude: artifacts, thinking panel and web search

**Gate**: every artifact type, the thinking panel and web-search results are
fixture-tested and verified into all six registered export formats.

```bash
pnpm typecheck && pnpm test:run && pnpm build
```

## Why

`ClaudeParser.extractArtifacts` maps a `typeLabel` string to a type with a chain
of `includes()` checks against **both English and Spanish** labels ("Imagen"/
"Image", "Documento"/"Document", "Diagrama"/"Diagram", "Código"/"Code"). That is
locale-dependent selection — it silently yields `type: 'unknown'` on any other UI
language. Verify against a real capture and decide whether an icon or
`data-*` attribute is a more durable signal than the visible label.

The thinking panel is not extracted at all. Web search is extracted but its
selectors are Tailwind utility chains
(`div.ease-out.transition-all.flex.flex-col.font-ui`), which
`docs/dev/parser-gotchas.md` §8 rules out as fragile.

## Work

Load the **parser-generator** skill first.

1. Re-derive artifact selection from something locale-independent.
2. Extract the thinking panel, or record a deliberate decision not to (Gemini's
   was dropped for size — 60k of internal narration — with a `ponytail:` comment
   naming the upgrade path; do the same rather than leaving it undecided).
3. Replace the Tailwind-chain web-search selectors with durable ones.
4. Sanitized fixture per widget + a selector-liveness guard for each selector.

## Note

`CLAUDE_SELECTORS` holds ~26 entries but `claude/parser.ts` reads only ~5 —
the other 22 `querySelector` calls inline Tailwind chains directly. Bringing
them into the SelectorSet with a liveness guard is the same fix `lo-4cdc` made
for ChatGPT and is in scope here.
