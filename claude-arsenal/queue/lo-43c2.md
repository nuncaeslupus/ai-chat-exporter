# Payload: D-17 — a locale lookup that can never hit

## Acceptance gate

**Gate**: `getPlatformName('chatgpt')` and `getRoleName('chatgpt')` resolve the
declared locale key instead of falling through to the hardcoded fallback.

```bash
pnpm lint && pnpm typecheck && pnpm test:run
```

## The defect

Found by the R8 i18n audit (`lo-d438`, PR #126). `src/shared/i18n.ts` builds the
message key with `id.charAt(0).toUpperCase() + id.slice(1)`, so `'chatgpt'`
produces `platformChatgpt` — but the bundles declare `platformChatGPT`. The lookup
always misses and falls through to the hardcoded `'ChatGPT'`.

**Nothing is user-visible today**: the fallback returns the right string, which is
exactly why this survived. It is dead weight plus a trap — the next platform whose
id capitalizes irregularly gets a silent miss with a worse fallback.

The audit kept the correctly-spelled keys rather than deleting them, since they
are what a fixed capitalizer would look for.

## Work

Map ids to display names explicitly instead of deriving the key from the id — the
registry already knows each platform's proper name. Whatever the shape, a test
must assert the locale value is returned, not the fallback (today's tests pass
either way, which is the reason this was invisible).

## Location

`src/shared/i18n.ts`, `_locales/*/messages.json`, `tests/`.
