# Payload: lo-f132 — ChatGPT Deep Research is unreadable and exports as junk

**Unparked 2026-07-29.** The earlier block ("needs a paid account") was wrong for
Deep Research — the owner reached it on their plan and captured it. Canvas and
image generation remain uncaptured.

## Acceptance gate

**Gate**: a conversation containing a Deep Research answer never exports the
string `ChatGPT said:` as that answer, and a Deep-Research-only conversation is
not reported as "no conversation to export".

```bash
pnpm lint && pnpm format:check && pnpm typecheck && pnpm test:run && pnpm build
```

## Root cause — measured, not inferred

ChatGPT renders a Deep Research report inside a **cross-origin sandboxed iframe**:

```html
<iframe title="internal://deep-research"
        src="https://connector-openai-deep-research.web-sandbox.oaiusercontent.com?app=chatgpt&…"
        sandbox="allow-scripts allow-same-origin allow-forms">
```

The turn itself carries **nothing else**: no `data-message-author-role`, no
`.markdown.prose`, no `data-message-id` — only a timestamp header and that frame.
The report is on a different origin the extension has no permission for, so a
content script in the ChatGPT page cannot read it, and neither can a
`document.documentElement.outerHTML` capture.

## The two symptoms this produces (both reproduced)

Run against `tmp/examples/chatgpt-conversation-with-deep-research.html` with the
current parser:

```
pairs: 2
  [0] Q(121): Deep research I need to find out how firemen stop fires…
       A(13):  ChatGPT said:          ← the entire report, replaced by the sr-only label
  [1] Q(24):  Great! Make me a summary
       A(2583): Here's a concise summary of the key ideas…
```

1. **Mixed conversation** — parses, pairs correctly (the `D-13` fix holds), but the
   Deep Research answer becomes the literal string `ChatGPT said:`. Worse than
   empty: it looks like content.
2. **Deep-Research-only conversation** — zero complete pairs, so the popup reports
   "no conversation to export here". This is what the owner originally reported as
   "the extension does not detect ChatGPT pages". `tmp/examples/chatgpt-conversation-deep-research-*.html`
   are that case (the two compacted/expanded captures are **byte-identical** —
   expanding the panel changes nothing, unlike Gemini).

A plain conversation parses perfectly — title, model `gpt-5-5`, all pairs — so
**no ChatGPT selector has rotted**. Do not go looking for that.

## The fork — the owner decides, do not assume

Reaching the report needs `https://*.oaiusercontent.com/*` in `host_permissions`
plus a content script with `all_frames: true` matching it, which relays the report
to the page's content script. The frame carries `allow-scripts allow-same-origin`,
so injection is technically possible. Cost: a broad permission over an OpenAI
user-content domain, another store review, and a `docs/PRIVACY.md` update.

**Whatever is decided, the fallback must land either way**: never emit
`ChatGPT said:` as an answer. A labelled placeholder naming the widget, and the
report's own link if one is reachable, is strictly better than fabricated text —
the same principle as `D-18`.
