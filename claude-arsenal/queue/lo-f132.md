# Payload: lo-f132 — ChatGPT: Deep Research, Canvas and image generation

## Acceptance gate

**Gate**: each widget below is captured, fixture-tested, and verified to survive
into all six registered export formats.

```bash
pnpm typecheck && pnpm test:run && pnpm build
```

## Why

The Gemini Deep Research work (`lo-1316` / PR #55) proved the pattern: a widget
renders **outside** the turn container the parser loops over, so it is dropped
silently with no error. ChatGPT's equivalents were never surveyed — the
2026-07 survey ran on a Free-tier account that could not reach them.

`ChatGPTParser` already has `extractCanvasContent`, `extractGeneratedImage` and
`extractDeepResearchInfo`, but none are verified against a real capture of those
features, and `extractDeepResearchInfo` only scrapes a summary line
(duration/sources/searches) — not the report body.

## Blocked on a human

**A capture is required and cannot be produced by an agent**: these features need
a paid account and a real interaction. Ask the user to run, on a conversation
containing the widget:

```javascript
copy(document.querySelector('main').outerHTML)
```

saving to `tmp/examples/chatgpt-<widget>.html` (gitignored). One capture per
widget class. Note from the Gemini work: a panel may only exist in the DOM while
it is **open** — capture with the widget expanded, and record in the payload
whether it collapses.

## Work

Load the **parser-generator** skill first; follow its widget-coverage matrix and
live-verification workflow.

1. Deep Research — find where the report body and its sources live. Reuse the
   shapes Gemini settled on (report merged into the answer, cited sources in
   `metadata.webSearches`) unless the DOM makes that wrong.
2. Canvas / textdoc — `[id^="textdoc-message-"]` is the current guess and has
   **no fixture coverage**; the liveness test asserts it matches zero.
3. Image generation — same, `generatedImageContainer` has no coverage.

Derive a sanitized fixture per widget (invented prose, structure preserved) and
add a selector-liveness guard for every new selector.

From the "+" menu on gemini.google.com (user screenshot). Each entry is a tool
that produces a distinct output widget in the conversation:

| Tool | Output widget | Status |
|---|---|---|
| Upload files / Add from Drive / More uploads | user attachment | not surveyed |
| Create image | generated image | `generatedImageContainer` exists, **no fixture coverage** |
| Create video | video player | **model cannot represent it** — see `lo-6fe5` |

| Canvas | immersive panel (sibling of chat history) | not surveyed |
| Deep research | immersive panel + source lists | **DONE** (PR #55) |
| More tools → Guided learning | unknown | not surveyed |

Composer also shows the model as **"Pro" / "Extended"** — that is the tier label
`lo-3c90` found where `getModel()` expects a model name.

**Canvas is the highest-value unsurveyed one**: Deep Research proved Gemini
renders these in `immersive-panel`, a *sibling of the whole chat history*, not
inside `.conversation-container`. Canvas almost certainly does the same, so the
turn loop will never see it. Start there and reuse the Deep Research approach.
