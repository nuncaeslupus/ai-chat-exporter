# Payload: ChatGPT reports "no conversation to export"

Reported by the repo owner, 2026-07-29, on the **unpacked dev build** (all of the
2026-07-28/29 session merged): opening the popup on a ChatGPT conversation shows
the not-supported screen. Claude and Gemini work.

## Acceptance gate

**Gate**: a ChatGPT conversation is detected and exports, and the popup never
shows "no conversation to export here" for a page whose URL is supported.

```bash
pnpm lint && pnpm format:check && pnpm typecheck && pnpm test:run && pnpm build
```

## Two defects, and the second hid the first

### 1. The popup conflates "unsupported page" with "parse found nothing"

`src/extension/popup/popup.ts`, `checkCurrentPage()`:

```ts
} else {
  // Content script loaded but no conversation found
  this.setUiState('unsupported');
  this.updateStatus('warning', getMessage('statusNoConversation'));
}
```

The **URL gate passed**, the content script **answered**, and the parse returned
nothing — yet the user is shown the same screen as a genuinely unsupported site,
complete with "open a chat on one of these pages" links, while standing on one of
those pages. The status text differs; the screen does not.

Fix: give a supported-page-with-no-conversation its own state. The reader needs to
know the page is right and the *extraction* failed — that is a bug report, not a
navigation prompt. This is worth fixing regardless of the ChatGPT cause, and it
makes the next occurrence diagnosable.

### 2. Why ChatGPT specifically returns nothing

Unknown, and **not diagnosable without a capture**. What is already ruled out:

- URL patterns are correct — `chatgpt.com` and `chat.openai.com` in
  `CHATGPT_URL_PATTERNS`, in the manifest `matches`/`host_permissions`, and in the
  built `dist/chrome/popup/popup.js`.
- `canParse()` only tests the URL, so it passes.
- The registry contains `chatgpt`.

That leaves the parser's own selectors. Both other platforms drifted this same
week — Gemini's title selector matched zero elements (`lo-3c90`), Claude's
`chat-title-button` was renamed to `chat-title-split` — so ChatGPT DOM drift is
the leading hypothesis, not a guess pulled from nowhere.

**Needs a capture first** (free tier is sufficient — this is ordinary conversation
detection, nothing paid):

```javascript
const a = document.createElement('a'); a.download = 'chatgpt-conversation.html';
a.href = URL.createObjectURL(new Blob([document.documentElement.outerHTML], {type:'text/html'})); a.click();
```

saved to `tmp/examples/` (gitignored — real conversation data never gets
committed; build fixtures with invented prose).

## Order

Defect 1 can be fixed now and is independent. Defect 2 waits on the capture. If
they are split, do 1 first — it is what makes 2 legible next time.
