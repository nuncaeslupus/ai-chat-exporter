## Acceptance gate

**Gate**: a ChatGPT Deep Research answer exports with the report's real text, and
when the frame cannot be read the export falls back to `lo-f132`'s placeholder
rather than failing or emitting fabricated content.

```bash
pnpm lint && pnpm format:check && pnpm typecheck && pnpm test:run && pnpm build
```

## What is known

The report renders in:

```html
<iframe title="internal://deep-research"
        src="https://connector-openai-deep-research.web-sandbox.oaiusercontent.com?app=chatgpt&…"
        sandbox="allow-scripts allow-same-origin allow-forms">
```

`allow-same-origin` + `allow-scripts` means the framed document keeps its origin
and runs scripts, so a content script matching that origin with
`all_frames: true` can run inside it and relay the report out.

## What this costs, and must therefore be justified in the PR

- `https://*.oaiusercontent.com/*` in `host_permissions` and `content_scripts.matches`
- a **second** store re-review (the first is `scripting`, from PR #116, still pending)
- a `docs/PRIVACY.md` update — it enumerates permissions and states what is read

Scope the match as narrowly as the sandbox host allows. Prefer
`https://*.web-sandbox.oaiusercontent.com/*` over the whole user-content domain
if it matches reliably; say which you chose and why.

## Design notes

- The framed script cannot talk to the page's content script directly; relay via
  `chrome.runtime` messaging through the background worker, or have the frame
  script send its payload keyed by `turn-id` for the parent to reassemble.
- **This is undocumented, private markup on a sandbox origin.** It can change
  without notice. Whatever selector you use, failure must degrade to `lo-f132`'s
  placeholder, never to an exception or fabricated text — and the test must prove
  that degradation, not just the happy path.
- The report may be long; check whether the frame renders it fully or virtualises
  it while scrolling, the way a long list would.
